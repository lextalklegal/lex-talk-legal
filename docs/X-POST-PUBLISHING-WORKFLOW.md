# Lex Talk Legal — X-post to news-article publishing

This workflow is triggered only by an editor-supplied X/Twitter post. The retired YouTube/Gemini auto-article generator is not part of this workflow.

## Current site architecture

Lex Talk Legal is a static HTML/assets site built by `scripts/build_site.py` and deployed to Cloudflare Workers by `.github/workflows/deploy-worker.yml`. Article pages, category cards, homepage selections, canonical/Open Graph/NewsArticle markup, related stories, `sitemap.xml` and `news-sitemap.xml` are built from editorial data. The shared global header, navigation and footer are preserved.

## How an X post is published

1. The editor supplies the official X embed code or original post URL in the conversation.
2. Extract the canonical status URL in the form `https://x.com/<handle>/status/<numeric-id>`. Preserve author attribution. Do not store arbitrary supplied embed scripts.
3. Research the underlying development. Prefer official orders, government releases, court records, statements from the named parties and reliable independent reporting. State what is confirmed separately from what a post claims.
4. Prepare a complete record in `data/x_articles.json`. The article body should begin with a standfirst such as `<p class="article-intro">…</p>`, followed by descriptive H2 sections, verification/limitations where appropriate, direct references, and any relevant disclosure. Use only factual dates and quotations grounded in sources.
5. Set `source_url` and `x_post_url` to the same canonical X status URL. This status URL is the stable duplicate key. If coverage of the same post already exists, update the existing record rather than adding another. If the story materially progresses, update the existing story or create a clearly differentiated follow-up linked to prior coverage.
6. Choose a unique route such as `/article/descriptive-headline-slug.html`; preserve that route when updating the story. `published` and `updated` must be ISO-8601 timestamps with timezone information. Categories must be one of: `Courts`, `Law & Policy`, `Banking Law`, `DRT / DRAT`, `Legal Careers`, `DRA`, `Explained`, or `Legal News`.
7. Commit the record to `main`. A push that changes `data/x_articles.json` triggers the editorial build. The build sanitizes ordinary article HTML, adds X's official widget from the canonical post URL with a fallback link, generates the page and structured data, refreshes category/homepage content and both sitemaps, then commits rendered output. That output commit triggers Cloudflare Worker deployment.
8. Verify the article page, X widget/fallback, canonical URL, source citations, mobile layout, and sitemap output before reporting it live. A green deployment alone does not guarantee X's third-party embed renders in every browser or network.

## Record format

```json
[
  {
    "title": "A factual SEO headline",
    "url": "/article/a-factual-seo-headline.html",
    "source_url": "https://x.com/example/status/1234567890123456789",
    "x_post_url": "https://x.com/example/status/1234567890123456789",
    "published": "2026-10-21T12:00:00+05:30",
    "updated": "2026-10-21T12:00:00+05:30",
    "labels": ["Legal News", "Courts"],
    "category": "Legal News",
    "image": "",
    "excerpt": "A short factual standfirst.",
    "meta_description": "A unique, factual search description for the article.",
    "content": "<p class=\"article-intro\">Summary...</p><h2>What happened</h2><p>Source-grounded reporting...</p><h2>Verification and context</h2><p>...</p><h2>Sources and references</h2><ul><li><a href=\"https://official.example/source\">Official source</a></li></ul>"
  }
]
```

The source file is initially an empty JSON array. Body content is sanitized to ordinary article HTML; the official X widget and script are generated by the builder from `x_post_url`. A record must not include a script tag or iframe.

## Editorial and technical safeguards

- Do not present allegations, predictions or political claims as established facts. Attribute them.
- An X embed proves what the post displays; it is not independent verification.
- Do not invent engagement counts, post timestamps, statements, court orders, legal citations, images or URLs.
- Do not copy/host the source video unless there is a valid basis; let X's widget display media it supports.
- Only use representative images the publisher is permitted to use. If none is available, leave `image` empty and the publisher logo remains the site-wide social fallback.
- Never put API keys, private notes, payment information or credentials in this source file.
- Existing YouTube-generated articles remain as historic content; no future YouTube upload is automatically converted to a blog.
- This workflow does not promise search rankings or instant indexing; verify metadata and sitemap output after publishing.
